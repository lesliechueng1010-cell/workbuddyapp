# 云峰鲜果 · 水果生鲜订购 App

一个面向**水果生鲜门店**的移动端 H5 应用原型，同时覆盖三种业务模式：**外卖到家**、**社区团购**、**企业采购**，并配套一套完整的**商家管理后台**（商品、库存、销售盘点、自动对账、拍照入库）。

原型参考了森果云店上的真实门店「云峰水果大卖场」（南京本地 10 余年水果生鲜店）。

---

## 一、这个 App 做什么

### 顾客端（`index.html`）

| 模块 | 说明 |
| --- | --- |
| 三种业务模式 | 顶部一键切换，共用一套商品库，价格体系各自独立 |
| 🛵 外卖到家 | 零售价，南京市区 2 小时达，满 39 元免配送费 |
| 👥 社区团购 | 团购价（比零售低约 15%），选团长 + 自提点，显示拼团进度与倒计时 |
| 🏢 企业采购 | 阶梯批发价（量越大越便宜），对公账期 30 天、增值税专票、满 1000 专车配送 |
| 会员与积分 | 4 档等级按累计消费自动升级（普通 / 银卡 / 金卡 / 钻石），享 9.5~9.2 折与 1~2 倍积分 |
| 在线充值 | 充 100 送 10 到充 3000 送 700，余额实时到账并生成对账流水 |
| 会员卡结账 | 结算页可选会员卡余额 / 微信支付 / 对公转账；100 积分抵 1 元，最高抵 20% |
| 优惠券 | 新人券、团购券、企采满减券、全场折扣券，结算时自动校验适用范围与门槛 |
| 订单跟踪 | 完整状态流 + 物流时间线（待付款 → 待接单 → 配送中 → 已送达 / 待成团 → 待自提 → 完成） |
| 售后退款 | 6 种原因一键申请，退款原路退回或退回会员卡，同时回滚库存 |

### 商家后台（`admin.html`，10 个页面）

- **经营概览** — 6 个 KPI、14 天销售趋势、业务模式构成、待办直达、快捷操作
- **智能入库** — 📷 拍照 / 上传入库单，自动识别明细后一键入库（见下文）
- **销售盘点** — 日销售额趋势、分类销售占比、热销商品 TOP 10
- **自动对账** — 逐日勾稽「系统应收（销售额 − 退款）」与「资金实收（在线收款 + 会员卡核销 − 退款）」，差异标红、平账打勾，附资金流水明细
- **订单管理** — 筛选、接单发货、标记送达、标记收款
- **企业采购审核** — B 端采购单审批、对公账期、开票状态
- **售后处理** — 退款工单，同意 / 驳回
- **商品管理** — 上下架开关、三档价格改价、进价与毛利率
- **库存盘点** — 安全库存预警、周转率、盘点调整、出入库流水
- **会员管理 / 充值与余额** — 等级分布、权益配置、预收负债

### 📷 智能入库（拍照识别入库单）

1. 拍照或上传入库单照片（也可使用内置示例单据）
2. 自动识别：版面分析 → 字段抽取（商品名 / 规格 / 数量 / 单价 / 金额，并做金额勾稽校验）→ 按名称与别名库匹配系统 SKU → 给出逐行置信度
3. 人工校正：勾选行、切换关联商品、改数量与进价、删除误识别行
4. 一键入库：批量写入库存、更新商品进价、生成出入库流水与采购付款流水
5. 入库单历史：随时查看明细，**一键撤销**会自动反向扣减库存并冲销采购流水

## 二、技术栈

- **零依赖、零构建**：原生 HTML + CSS + 原生 JavaScript（ES5/ES6 语法，无框架、无打包器）
- **无任何 CDN 引用**：图表用 CSS 条形图 + 内联 SVG 手绘，商品图用 emoji，离线可跑
- **状态管理**：自研极简 store，全部数据落地 `localStorage`（键名 `yunfeng_fresh_state_v1`），刷新不丢
- **Canvas**：用于绘制仿真入库单示例图、上传图片压缩、图片指纹计算
- **浏览器支持**：现代浏览器（Chrome / Edge / Safari），移动端优先（430px 手机外壳 + 底部 Tab 栏）

没有 `package.json`，也没有 `node_modules` —— 这是有意保持的：打开就能跑，不需要 npm install。

## 三、怎么跑起来

### 方式一：本地静态服务器（推荐）

```bash
cd yunfeng-fresh

# Python 3
python -m http.server 8099

# 或 Node
npx serve . -l 8099
```

然后浏览器打开：

- 顾客端：<http://localhost:8099/index.html>
- 商家后台：<http://localhost:8099/admin.html>

### 方式二：直接双击打开

直接双击 `index.html` / `admin.html` 也能运行（纯静态、无跨域请求）。用服务器方式是为了让 `localStorage` 有稳定的 origin，避免 `file://` 下数据串用。

### 方式三：部署到线上

整个目录是纯静态资源，直接上传到任意静态托管（GitHub Pages、Vercel、Netlify、Nginx、腾讯云 COS 等）即可，无需构建步骤。

### 体验建议

1. 先打开顾客端，在首页切换「外卖 / 团购 / 企业采购」三个模式，观察同一商品的三套价格
2. 加购物车 → 结算（可试会员卡余额、积分抵扣、优惠券）→ 提交订单 → 选支付方式
3. 到「订单」页推进订单状态、申请售后
4. 到「我的」页做一次在线充值，看余额与积分变化
5. 打开后台，先看概览，再进「智能入库」点一张示例单据走完整流程
6. 想恢复初始状态：顾客端「我的 → 重置演示数据」

## 五、接入真实 OCR（可选）

内置的是**演示识别引擎**：它会真实读取上传图片的像素指纹，并对单据文本做正则解析、金额勾稽校验和别名匹配，但不是通用文字识别。接入真实 OCR 不需要改动解析 / 匹配 / 入库逻辑，只需在浏览器控制台或你自己的启动脚本里配置：

```js
YF.ocr.configure({
  endpoint: 'https://your-ocr-api/recognize'   // 后端接口地址
  // token 由后端校验，见下方安全说明
});
```

后端只需返回：

```json
{
  "supplier": "南京众彩农产品物流配送中心",
  "no": "RK20261022001",
  "date": "2026-10-22",
  "raws": ["阳光玫瑰葡萄      500g/盒        50    26.50    1325.00"]
}
```

推荐使用腾讯云 / 百度智能云的通用印刷体票据识别。

## 六、安全说明

- 仓库中**不包含任何 API Key、密码、Token 或私钥**。所有凭据相关字段（`ocr.js` 中的 `endpoint` / `token` / `headers`）默认为空，仅在运行时由调用方传入。
- 接入真实 OCR 时，请**不要**把密钥写进前端代码。正确做法是让你的后端代理 OCR 请求，前端只请求你自己的接口。
- 所有数据均为演示数据，保存在浏览器 `localStorage`，不会上传到任何服务器。
